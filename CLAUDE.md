# Last Stop

Unity 6 (6000.6.5f1, URP, Forward+) first-person horror game. Current scene: `Assets/Scenes/LookTest.unity`.

## Source of truth

`docs/game-design/last-stop.md` is the blueprint. Read it before planning any feature. If a request conflicts with it, point out the conflict and ask; don't silently deviate. Add every new creative decision there.

## Working with the user

- The user is a **beginner** and the **creative director**. Explain what you do in plain words, without jargon (or define it when you must use it).
- **Every request:** before building, ask the creative questions as a short **multiple-choice** list (recommendation first). Then build it, test it in the Editor, and tell the user what to try.
- **Creative choices are theirs:** names, numbers (speeds, timers, counts), art direction, colours, feel.
- **Technical choices are yours:** decide architecture, components, physics and file layout yourself, and briefly say what you picked.

## Building scenes

- Scenes are generated by editor scripts (e.g. `Assets/Editor/LookTestBuilder.cs`, menu **Last Stop → Build Look Test**).
- To change the scene, edit the builder and re-run it. Hand edits to the generated scene are lost on rebuild.
- Walls and floors are boxes with world-space UVs, so textures line up across pieces. Set the metres-per-tile per material.
- **No overlapping surfaces (z-fighting).** When two boxes share a face plane facing the same way, their textures flicker and tear in jagged stripes.
  - Build pieces with `Span(min, max)` so they meet **edge to edge**: one piece ends exactly where the next begins.
  - Walls run full height; ceilings and floors fit between the walls.
  - Flat decals (puddles, signs) sit at least 1 cm off the surface behind them.
  - Every builder must call `GeometryCheck.Find(root)` before saving and end with **0** warnings. It can also be run from **Last Stop → Check Geometry**.
- **Lighting rules:**
  - **Keep surfaces reasonably light** (concrete and gravel tints about 0.5–0.6). Darkness should come from missing light, not from black textures, or the flashlight has nothing to show.
  - URP lights fade with distance squared, so high lamps need large intensities (the platform lamps use 45, the corridor lamps 16, the flashlight 20).
  - Glowing tubes use the **Unlit** shader with an HDR colour, because the Lit `_EMISSION` keyword got switched off.
  - Puddle reflections come from a reflection probe **baked at build time** (`Assets/Lighting`), because realtime probes are off in the quality settings.

## Gameplay systems

- **Anything that moves must not be static.** The builder marks level objects static (merged for speed); objects under a `HingedDoor` are excluded. A static object's hinge turns but its drawn mesh stays frozen. Test moving things with a screenshot, not just by reading their angle.

- **Saving:** `SaveSystem` writes `SaveData` as JSON to `Application.persistentDataPath/Saves` (slot 0 = autosave, 1-5 = player). When a feature has state worth keeping, add it to `SaveData` and to `SaveSystem.Capture`/`ApplyPending`, plus a quiet "put back" method on the component (like `FuseBox.SetInstalled`, `PowerGrid.RestoreQuietly`, `HingedDoor.OpenNow`). Pickups and doors are found by hierarchy path + sibling index, recorded in `SaveSystem.RememberLevel` at level start. Loading reloads the scene; `MenuSystem.Start` sees `SaveSystem.Pending`, skips the title and applies it. One-time intro events must check `SaveSystem.LoadedGame`. The save/load screen is `SaveMenu` (on the Menus object). Saves made during tests stay on disk: delete `%USERPROFILE%\AppData\LocalLow\DefaultCompany\LastStop\Saves` afterwards.
- **IMGUI styles kept in fields** can come back from an editor reload with stale settings: mark them `[System.NonSerialized]` and set alignment/wrap every frame.

- **Station 2 (Canal St Junction)** is built in the same scene beyond z 300 (`LookTestBuilder.Canal.cs`); `SaveSystem.IsCanal(p)` (z > 250) tells the stations apart. It has its own `PowerGrid` (`ownsUnassignedLamps = false`): its lamps set `PoweredLight.grid`. `StationTransfer` fades and teleports the player there, `CanalArrival` drops Frankie 60 s later. To test: New game, `FrankieArrival.WakeNow()`, set `CanalArrival.delay` high, then `StationTransfer.Begin(player, null)`.
- **Stalled carriages:** `SubwayCarOpen.fbx` (both end doorways widened) and `SubwayCarEnd.fbx` (one end wall, the cab partition placed by `LookTestBuilder.CabPartition`) are made from the Metro kit by `Tools/Blender/widen_car.py`. Every carriage is scaled to `CarLength` (18.7 m): that makes the doorway 0.9 x 1.95 m, the minimum the player's capsule (0.7 x 1.8 m plus 8 cm skin each side) gets through, and still clears the 3 m tunnel ceilings. Raising the doorway in the model breaks the wall around it.
- **Textures on objects:** materials listed in `LookTestBuilder.fitToPiece` (doors, lockers, cabinets, crates) stretch their image over each face instead of tiling in world space; add a material there when a hand-built object shows a seam. Track beds need their own material per bed with `tileOrigin` at the bed's edge.
- **Lower levels (both stations):** `LookTestBuilder.ServiceIndustrial.cs` dresses Hollis St's; Canal St's is `LookTestBuilder.CanalLower.cs`, drawn as a character map (`LowerMap`, 2 m cells: `#` solid, `.` corridor, `H` hall, `d` doorway) that `GridLevel` turns into walls, floors and ceilings meeting edge to edge. Shared pieces in `LookTestBuilder.Industrial.cs`: `ChainFence` / `FencedCage` (mesh on layer 2 so rays see through; a carving `NavMeshObstacle` keeps Frankie out), `Pipe` / `PipeRun` (8-sided, no colliders), `CagedBulb` (intensity x20, the concrete down there is dark), `ControlPanel` (switch boxes + cable bundles; never reuse the circuit-breaker model for decoration, it is the objective fuse box), `ElectricCabinet`, `Conduits`, and `WalkLink`. See-through quads need two faces back to back (`ChainFence`): a double-sided material lights the back face as if it faced away, so it goes black. The maintenance door and stairs are `BuildMaintenanceDoor` / `BuildStairwell` with an offset (`CanalLowerOffset`).
- **Frankie on stairs and through doorways:** his walkable area is built for a 0.5 m radius, so 1 m doorways and stair flights don't connect. `WalkLink` adds a NavMeshLink with a `LinkPath` (points to walk; FrankieAI walks them instead of jumping), switched off while its `gate` door is shut. Check reachability with `NavMesh.CalculatePath` (edit mode treats every link as on).
- **Lockers:** `HidingLocker.SeenGettingIn` is true if Frankie sees the player or is chasing and saw them in the last 3 s; then FrankieAI's `BreakIn` mood slams the door (`HidingLocker.Bang`) `lockerBangs` times and calls `PullOut`.
- **Hollis St wake-up:** `BelowTrigger` (bottom of the service stairs) calls `FrankieArrival.PlayerWentBelow`; he appears at `belowAppearSpot` and `FrankieAI.SearchFor`. To test, disable `BelowTrigger`s (and `FrankieArrival`) when taking screenshots below.
- **Canal St ending:** `EmergencyLatch` (lid opens once `canalGrid.IsOn`, then Interact shows the `EndCard`); the street shutter is a `JammedShutter`. `RollerShutter` and `CanalExit` were removed.
- **Frankie jumps links himself** (`autoTraverseOffMeshLink` is off; `FrankieAI.Leap` arcs across and calls `CompleteOffMeshLink`). Platform edges get links from `EdgeLinks` (Monster.cs): a link's platform end must sit inside the walkable area (0.9 m in from the edge), or it silently never connects; check with `NavMesh.CalculatePath` lengths. His swipe hits only within `hitArc` of straight ahead. Sprint stamina lives in `PlayerMovement` (`Stamina`, `Winded`).
- **Frankie's sight** scales with how lit the player is (`LightLevel.At`, ignoring the player's own torch): `darkSightRange` 4 m to `sightRange` 15 m, `torchSightRange` 25 m with the torch on.
- **Interaction:** `Interactor` (on the camera) casts a ray using `PlayerRay`, which skips the player's own capsule. Anything with `IInteractable` (Prompt + Interact) gets "[E] prompt".
- **Power:** `PowerGrid` (one per area) plus `PoweredLight` on every lamp. Things that need power listen to `PowerGrid.Restored` (see `HingedDoor.needsPower`).
- **Pickups:** `Pickup` (Fuse, Battery, Shotgun, Shell). Counts live in `PlayerInventory`.
- **Held gun and arms:**
  - They sit on rendering layer `ViewmodelLayer` (Light Layer 1). The torch lights skip it; a faint `ViewmodelFill` light follows the torch.
  - Arms model: `PsxArms` (imported as Legacy animation; `ArmsController` plays `ArmsRig|grab.R` on `Interactor.Interacted`). Placed by its `camera` bone on the player camera, plus `ShoulderOffset` so the elbows can bend.
  - **Hand-pose lesson:** a left hand palm-up with fingers forward has its thumb pointing LEFT; finger curl is positive toward the palm. If the target is beyond arm reach (upper + lower length) the arm goes straight: check the distance first.
  - `ArmsRig` uses two-bone IK, sets each hand's direction (fingers/thumb in grip space), rolls the forearm with the hand (`forearmRollShare`) so the wrist doesn't tear, and curls the fingers.
  - Tune poses with a side-view debug camera.
- **Flashlight** softens its beam when the surface ahead is close (`fullStrengthDistance`), so it doesn't blind you up close but still reaches 60 m.
- The test-area builder is split into `LookTestBuilder.cs` (layout) and `LookTestBuilder.CoreLoop.cs` (gameplay pieces). Model helpers: `Model`, `ModelPiece`, `StandOn`, `MakePickup`.

## Driving the Unity Editor

- Run `unity status` first. Change scenes through the Editor (`unity command eval_file --file <abs path>`), not by hand-editing `.unity` files.
- Eval files are method bodies with fully qualified names. Put them in the project's `Temp/` folder and delete them afterwards.
- **Any Play-mode eval must start with `if (!UnityEngine.Application.isPlaying) return ...;`**.
- After `editor_play`, set `Application.runInBackground = true` so Play mode keeps running when Unity isn't focused. Afterwards, in edit mode, set `PlayerSettings.runInBackground = false` and check `ProjectSettings.asset` still says `runInBackground: 0`.
- **Simulating keys while Unity is in the background** (real keyboards are ignored then). In each new Play session, do this in order:
  1. Set `InputSystem.settings.backgroundBehavior = IgnoreFocus` and `editorInputBehaviorInPlayMode = AllDeviceInputAlwaysGoesToGameView`, then assign `InputSystem.settings = s`.
  2. Add a fresh `InputSystem.AddDevice<Keyboard>("TestKeyboard")` and call `.MakeCurrent()`.
  3. `QueueStateEvent(Keyboard.current, new KeyboardState(Key.W, ...))` presses keys; an empty `KeyboardState` releases them.
  - A device added before step 1 stays deaf. The settings are in memory only and reset with Play mode.
  - Game time runs on several seconds between evals, so measure with a recorder hooked to `InputSystem.onAfterUpdate` (store max speed/height on a temporary GameObject), not by reading positions later.
- The real mouse moves the camera while Play mode runs (cursor locked), so set the view right before each capture.
- `capture_game_view --save_path` only accepts paths inside the project and lands in `Assets/Temp`. Delete that with `AssetDatabase.DeleteAsset("Assets/Temp")` when done.
- **The game starts on the title screen** with the Player switched off. To test gameplay, start it first: call `MenuSystem`'s private `Choose()` with page `Main`, item 0 (New game) via reflection, and wait ~2 s for the fade. Capture menus with `capture_game_view --source screen` (`--source camera` misses on-screen UI).
- **Refresh and wait for compiling before entering Play mode.** If Unity recompiles during Play (it notices an edit late), every component loses its private data and floods the Console with null errors that are not real bugs.
- Settings live in PlayerPrefs (the registry). After testing settings, call `GameSettings.ResetToDefaults()` in edit mode. Key bindings are in PlayerPrefs too: call `Controls.ResetToDefaults()` as well.
- **Frankie (the monster)**: test with the player unkillable (`PlayerHealth.maxHits = 999`) and wake him at once with `FrankieArrival.ArriveNow()` (or `WakeNow()` + `PutBack`). Since 2026-10-28 his body is the Ridgeback (`Characters/Ridgeback`, Codyanka); it imports as **Generic** (his own skeleton, no retargeting). The old Big Frankie, Pale Man and TheWrapper models were deleted on 2026-11-02 (`Tools/Blender/convert_frankie.py` and `rig_paleman.py` only matter if they come back from the asset library). The builder stands him on the floor in his idle pose using his foot bones, and lowers the NavMeshAgent (`baseOffset`) by the gap between the walkable area and the real floor. Generic clips can be sampled in edit mode with `AnimationClip.SampleAnimation` (a PlayableGraph on an un-played instance did nothing). Each test run adds virtual devices; after many runs the Input System logs "Control count per binding" errors, which are a test artefact.
- **All gameplay input goes through `Controls`** (`Controls.Pressed(GameAction.X)`, `Held`, `Move`, `PadLook`, and `Ui*` for menus), never `Keyboard.current` directly, so rebinding and the controller keep working. Show keys in prompts with `Controls.Label(GameAction.X)`. To test a controller, `InputSystem.AddDevice<Gamepad>()` and queue `GamepadState`s. Display settings (vsync, fullscreen) only apply in builds, so Play mode never rewrites `ProjectSettings`.
- Exit Play mode (`editor_stop`) when testing is done.
